# 战略简报：开工前的一页纸

战略简报不是项目管理文档，也不是把任务拆成几十个 TODO。它的作用是让团队在扩大实现成本前，先对目标、边界、风险和证据达成共识。

## 六个问题

1. **结果是什么？**
   用户、业务或系统的哪个可观察行为要改变？用结果描述，不用“加一个接口”描述。
2. **谁会被影响？代价是什么？**
   明确直接用户、维护者和失败时受损的人；这决定风险预算。
3. **约束和不变量是什么？**
   哪些规则不能破坏，例如权限、数据一致性、兼容性、延迟、合规或可回滚性。
4. **这次明确不做什么？**
   把未来想象和本次承诺分开，防止范围膨胀。
5. **最小可交付切片是什么？**
   选择能产生真实反馈、能独立验证、最好能关闭或回滚的最小变化。
6. **怎样证明它有效，怎样撤回？**
   写接受标准、测试、指标、发布护栏和回滚路径；没有证据的“完成”只是主观感觉。

## 输出模板

```text
标题：
结果：
受影响者与失败代价：
约束 / 不变量：
本次不做：
最小切片：
验证证据：
发布与回滚：
最大未知数：
最便宜的验证方式：
```

## AI 协作顺序

1. 先自己写出目标、约束和不确定性，避免把空白交给模型填。
2. 让 AI 找出隐含假设、反例、边界条件和可拆分切片。
3. 再让 AI 生成实现、测试或迁移草案。
4. 由人检查行为、设计、数据风险、可观测性和回滚，不把“代码能运行”当成证明。

## 一条判断标准

如果一个切片不能独立产生反馈，也不能独立验证或撤回，它通常还不是好的交付切片。
